# Подключение GetCourse

## Настройки

В `.env` задайте GC_ACCOUNT_URL (точный HTTPS-домен аккаунта), GC_API_KEY, GC_BASE_OFFER и GC_FULL_OFFER (уникальные коды предложений), GC_WEBHOOK_SECRET (случайные 48+ символов). Один код — программа 990 ₽, второй — доптариф 1990 ₽. Стоимости задаются BASE_PRICE и FULL_PRICE в копейках. Секреты не коммитьте.

На стороне сайта заказ сначала фиксируется в базе. Import API создаёт сделку с постоянным внешним номером `VP-<UUID заказа>`. Повтор попытки использует тот же номер; статус и факт оплаты в импорт не передаются, чтобы не сбросить существующую оплату. Используются `offer_code`, `deal_cost`, `quantity`, `deal_currency` и `return_payment_link=1`.

## Callback

Создайте процесс по заказам нужных двух предложений. При переходе в «Завершён» выполните операцию «Вызвать URL»:

- Метод POST.
- URL `https://your-domain.ru/api/getcourse/webhook`.
- Заголовок `X-Webhook-Secret`: значение GC_WEBHOOK_SECRET.
- Content-Type: `application/x-www-form-urlencoded`.

Поля тела (переменные GetCourse подставляются процессом):

```text
order_id={object.id}
order_number={object.number}
email={object.user.email}
status=payed
amount={object.cost_money_value}
currency=RUB
```

Отправляйте числовую стоимость в рублях; проверьте переменную стоимости в конструкторе своего аккаунта. Поле cost_money_value поддерживается документацией GetCourse и выводит стоимость без разделяющих пробелов. Принимаются суммы `990`, `990.00`, `990,00`, с необязательным RUB или `руб.`. Сумма должна совпадать с сохранённой стоимостью заказа. Частичная оплата доступ не открывает. Не передавайте секрет в URL.

При возврате настройте отдельный вызов того же URL с `status=refunded`. Удаление или изменение статуса заказа в GetCourse само по себе не отменяет нашу запись: процесс возврата должен вызывать endpoint либо статус должен попасть в сверку как cancelled. Обработчик отзывает доступ, выданный этим заказом; историю не стирает.

Добавьте ветку ошибки процесса: уведомление ответственного/повтор операции. Секрет в заголовке — наш способ аутентификации callback; он не называется встроенной HMAC-подписью GetCourse. Сайт не выдаёт доступ по редиректу после оплаты или email из браузера.

После оплаты настройте переход обратно на `https://your-domain.ru/app?payment=1`. Заказ сохраняется в sessionStorage сайта; кабинет опрашивает именно его статус. Во встроенном браузере с другой сессией потребуется обычный вход.

## Потерянные уведомления

Celery Beat раз в час запускает Export API по изменениям за последние 7 дней. Экспорт готовится асинхронно; фоновая задача опрашивает готовность, не задерживая API сайта. Используются ID заказа и номера выданных сайтом заказов. Чужие продукты общего GetCourse-аккаунта пропускаются. Для простоя дольше 7 дней выполните отдельную выгрузку и привязку через администратора.

Лимит запросов внутри приложения — 60 за 2 часа; он оставляет часть бюджета другим интеграциям. У GetCourse экспорт и ограничения общие на аккаунт. Если «Мой ритм» использует тот же аккаунт, согласуйте расписания сверок. На ознакомительном тарифе API недоступен.

Неопознанная оплата и несовпадение суммы сохраняются в «Оплатах». Администратор выбирает аккаунт, тариф и причину; уже выданный или возвращённый платёж повторно использовать нельзя. Оплаты на другую почту сопоставляются по сохранённому ID заказа, а не по почте.

## Сквозная проверка перед рекламой

На реальном аккаунте пройти: регистрация → создание заказа → реальная оплата → callback → месяц доступа → письмо → вход → 3 минуты просмотра → отметка и админка. Повторить callback, проверить продление и возврат, а также отправку с неправильным секретом.

Источники: [Import/Export API](https://getcourse.ru/help/api), [операция «Вызвать URL»](https://getcourse.ru/blog/276215).
